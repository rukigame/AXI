AXI Master와 Slave, 누가 무엇을 하나

칩 안에서 두 부품이 데이터를 주고받는 약속이 AXI입니다. 이 페이지는 그 약속에서 Master와 Slave가 각각 맡은 일, 그리고 지금 우리 코드가 어디까지 만들어졌는지를 회로를 몰라도 읽을 수 있게 정리했습니다.

01등장인물: 사물함 보관소 비유

회사 건물 1층에 사물함 4칸짜리 보관소가 있다고 생각해 보세요. 사장님이 지시를 내리고, 심부름 직원이 보관소에 가서 물건을 맡기거나 꺼내 옵니다.

HOST · 테스트벤치

사장님

"0x08번 칸에 이걸 넣어 와" 또는 "0x08번 칸에 뭐 있는지 봐 와" 하고 지시만 합니다. 신호로는 addr wdata write transfer를 주고, 일이 끝나면 ready로 보고받습니다.

MASTER · AXI_Master.sv

심부름 직원

대화를 먼저 시작하는 쪽입니다. 사장님 지시를 AXI 규칙에 맞는 신호로 바꿔 보관소에 전달하고, 결과를 받아 사장님께 보고합니다. CPU가 대표적인 Master예요.

SLAVE · axi_slave.sv

보관소 직원

요청이 오면 응답하는 쪽입니다. 스스로 일을 시작하지 않고, 들어온 주소에 맞는 사물함(레지스터)에 물건을 넣거나 꺼내 줍니다. 메모리, GPIO, 타이머 같은 주변장치가 Slave예요.

02둘을 잇는 다섯 개의 통로(채널)

Master와 Slave 사이에는 일방통행 통로가 다섯 개 있습니다. 쓰기(맡기기)에 3개, 읽기(꺼내기)에 2개를 씁니다. 통로마다 방향이 정해져 있어서 서로 부딪히지 않고 동시에 움직일 수 있습니다.

채널비유내용물VALID를 내는 쪽 → READY를 내는 쪽
AW 쓰기 주소"0x08번 칸에 넣을게요"AWADDRMaster → Slave
W 쓰기 데이터맡길 물건 건네기WDATAMaster → Slave
B 쓰기 응답보관 영수증BRESP (00 = OKAY)Slave → Master
AR 읽기 주소"0x08번 칸 꺼내 주세요"ARADDRMaster → Slave
R 읽기 데이터꺼낸 물건 돌려주기RDATA RRESPSlave → Master

03모든 채널의 공통 규칙: VALID와 READY 악수

다섯 채널 모두 같은 방식으로 물건을 건넵니다. 보내는 쪽은 VALID를 1로 올려 "줄 게 있어요"라고 알리고, 받는 쪽은 READY를 1로 올려 "받을 수 있어요"라고 답합니다. 클럭이 올라가는 순간 둘 다 1이면 전달이 끝납니다. 이를 핸드셰이크(악수)라고 부릅니다.

VALID=1, READY=0내밀었지만 상대가 아직 손을 안 내밈. 보내는 쪽은 VALID를 계속 1로 유지하며 기다려야 함.
VALID=0, READY=1받을 준비는 됐지만 줄 물건이 없음. 그냥 대기.
VALID=1, READY=1악수 성공. 이 클럭에서 내용물이 전달되고, 다음 클럭부터 둘 다 내려도 됨.

05Master: 지금 무엇을 구현했나

AXI_Master.sv는 다섯 채널마다 작은 상태 기계(FSM)를 하나씩 두었습니다. 상태 기계는 "지금 쉬는 중 / 지금 일하는 중" 두 상태만 오가는 스위치라고 생각하면 됩니다.

완료

AW · W 채널: 주소와 데이터 내밀기

사장님이 transfer=1, write=1을 주면 AWVALID와 WVALID를 1로 올리고, Slave의 AWREADY·WREADY가 올 때까지 기다렸다가 쉬는 상태로 돌아갑니다.

완료

B 채널: 영수증 받기

데이터를 내미는 순간(WVALID) BREADY를 1로 올려 영수증 받을 준비를 합니다. BVALID가 오면 쓰기가 끝난 것이므로 w_ready를 1로 만듭니다.

완료

AR 채널: 꺼낼 주소 내밀기

transfer=1, write=0이면 ARVALID를 올리고 ARREADY를 기다립니다.

완료

R 채널: 꺼낸 물건 받기

ARVALID를 낸 뒤 RREADY를 올리고 기다립니다. RVALID가 오면 rdata에 RDATA를 담고 r_ready를 1로 만듭니다.

완료

사장님께 보고: ready = w_ready | r_ready

쓰기든 읽기든 끝나면 한 클럭 동안 ready가 1이 됩니다. 사장님은 이걸 보고 다음 지시를 내립니다.

주의

사장님(테스트벤치)이 지켜야 할 두 가지

transfer는 1클럭만 1로 줘야 합니다. 계속 1이면 같은 쓰기를 반복합니다. 그리고 읽은 값 rdata는 ready가 1인 그 클럭에만 유효하므로 그때 받아 둬야 합니다.

06Slave: 어떻게 만들어야 하나

Slave는 Master의 거울입니다. Master가 VALID를 내면 Slave는 READY로 답하고, 응답 채널(B, R)에서는 반대로 Slave가 VALID를 냅니다. 보관소 안에는 32비트짜리 사물함 4칸이 있고, 칸 번호는 4씩 커집니다.

0x00addr[3:2]=00slv_reg0
0x04addr[3:2]=01slv_reg1
0x08addr[3:2]=10slv_reg2
0x0Caddr[3:2]=11slv_reg3

주소의 아래 두 비트는 항상 00이라서, 바로 위 두 비트 [3:2]만 보면 몇 번 칸인지 알 수 있습니다. 메모리 맵에서 디코더가 앞자리만 보고 칩을 고르던 것과 같은 원리입니다.

  1. 주소 받기 (AW, AR)

    AWVALID나 ARVALID가 오면 다음 클럭에 READY를 1로 올려 악수합니다. 악수하는 순간 주소를 내부 메모장(aw_addr_reg, ar_addr_reg)에 적어 둡니다. 악수가 끝나면 Master는 주소를 더 이상 붙들고 있지 않기 때문입니다.

  2. 물건 받기 (W)

    WVALID가 오면 WREADY로 답하고, 데이터를 w_data_reg에 적어 둡니다.

  3. 주소와 물건이 둘 다 왔을 때만 사물함에 넣기

    AW와 W 중 무엇이 먼저 도착할지는 정해져 있지 않습니다. 그래서 aw_done, w_done 표시를 두고 둘 다 1일 때 해당 칸에 넣습니다. 강의자료의 "Write transaction dependencies" 규칙입니다.

  4. 영수증 주기 (B)

    넣은 다음 BVALID=1, BRESP=00(OKAY)을 보내고, Master의 BREADY와 악수하면 끝납니다.

  5. 꺼내 주기 (R)

    AR 악수가 끝난 뒤에만 RVALID=1을 올리고, 적어 둔 주소의 칸 내용을 RDATA로 내보냅니다. Master의 RREADY와 악수하면 끝납니다.

사물함에 넣는 부분은 실제 코드로 이렇게 생겼습니다.

always_ff @(posedge ACLK) begin
    if (reg_we) begin                     // AW, W 둘 다 받은 순간
        case (aw_addr_reg[3:2])           // 몇 번 칸인지 고르기
            2'd0: slv_reg0 <= w_data_reg;  // 0x00
            2'd1: slv_reg1 <= w_data_reg;  // 0x04
            2'd2: slv_reg2 <= w_data_reg;  // 0x08
            2'd3: slv_reg3 <= w_data_reg;  // 0x0C
        endcase
    end
end
완료

현재 axi_slave.sv 상태

위 다섯 단계를 모두 구현했고, Master와 연결해 네 칸에 쓰고 다시 읽는 시뮬레이션을 통과했습니다.

read 0x00 = a0000000 · read 0x04 = a0000001 · read 0x08 = a0000002 · read 0x0c = a0000003 · read 0x08 = deadbeef → PASS

07axi_slave.sv 코드 읽기

현재 axi_slave.sv는 약 330줄입니다. 길어 보이지만 같은 모양의 블록이 채널마다 반복되는 구조라서, 한 채널만 이해하면 나머지는 이름만 바꿔 읽으면 됩니다. 위에서 아래로 파일 순서대로 설명합니다.

① 포트입출력 선언
② 메모장내부 변수
③ AWFSM + 주소 저장
④ WFSM + 데이터 저장
⑤ BFSM + 사물함 쓰기
⑥ ARFSM + 주소 저장
⑦ RFSM + 사물함 읽기

① 포트 선언: Master와 방향이 정반대

Master에서 output이던 신호는 Slave에서 input이 되고, 반대도 마찬가지입니다. 같은 전선의 양 끝이니까요. 단 ACLK와 ARESETn은 둘 다 바깥에서 받으므로 양쪽 모두 input입니다.

규칙은 간단합니다. Slave는 READY와 응답(B, R)을 내보내고, 나머지는 받기만 합니다.

// AW channel
input  logic [31:0] AWADDR,   // 받음
input  logic        AWVALID,  // 받음
output logic        AWREADY,  // 내보냄
...
// B channel
output logic [1:0]  BRESP,    // 내보냄
output logic        BVALID,   // 내보냄
input  logic        BREADY,   // 받음

② 내부 메모장: 이 모듈 안에서만 쓰는 변수

바깥과 연결되지 않고 Slave 안에서만 쓰는 변수들입니다. 보관소 직원의 사물함과 메모장, 체크 표시라고 보면 됩니다.

logic [31:0] slv_reg0, slv_reg1,
             slv_reg2, slv_reg3;   // 사물함 4칸

logic [31:0] aw_addr_reg,          // 받아 둔 쓰기 주소
             w_data_reg,           // 받아 둔 쓰기 데이터
             ar_addr_reg;          // 받아 둔 읽기 주소

logic aw_done, w_done, ar_done;    // "받았음" 체크 표시
logic reg_we;    // 사물함에 넣어라 (1클럭 펄스)
logic r_start;   // 꺼내 주기 시작 (1클럭 펄스)
체크 표시언제 1이 되나 (켜짐)언제 0이 되나 (꺼짐)왜 필요한가
aw_doneAW 악수 순간 AWVALID & AWREADY사물함에 넣는 순간 reg_we주소를 받았는지 기억
w_doneW 악수 순간 WVALID & WREADY사물함에 넣는 순간 reg_we데이터를 받았는지 기억
ar_doneAR 악수 순간 ARVALID & ARREADY꺼내 주기 시작 r_start읽기 주소를 받았는지 기억

③ AW 채널: 모든 채널의 기본 틀

채널 하나는 블록 세 개로 이루어져 있습니다. 이 틀을 이해하면 W, AR도 똑같이 읽힙니다.

  1. 상태 이름 정하기 (typedef enum): 쉬는 중 AW_IDLE, 받을 준비 AW_READY 두 가지.
  2. 상태 기억하기 (always_ff): 클럭이 올라갈 때마다 "다음 상태"를 "현재 상태"로 옮깁니다. 리셋이면 IDLE로.
  3. 다음 상태와 출력 정하기 (always_comb): 지금 상태와 들어온 신호를 보고 AWREADY 값과 다음 상태를 계산합니다.

맨 위의 AWREADY = 0; aw_state_next = aw_state;는 기본값입니다. 어떤 경우에도 값이 정해지게 해서, 원치 않는 기억 소자(래치)가 생기지 않게 합니다.

typedef enum logic {
    AW_IDLE = 0,
    AW_READY
} aw_state_e;

always_ff @(posedge ACLK) begin
    if (!ARESETn) aw_state <= AW_IDLE;
    else          aw_state <= aw_state_next;
end

always_comb begin
    AWREADY = 1'b0;              // 기본값
    aw_state_next = aw_state;    // 기본: 그대로
    case (aw_state)
    AW_IDLE: begin
        if (AWVALID & !aw_done)   // 주소가 왔고
            aw_state_next = AW_READY; // 아직 안 받았으면
    end
    AW_READY: begin
        AWREADY = 1'b1;          // "받을게요"
        if (AWVALID)             // 악수 성립
            aw_state_next = AW_IDLE;
    end
    endcase
end
왜 !aw_done을 같이 보나요?이미 주소를 받아 두고 아직 사물함에 넣기 전이라면, 새 주소를 또 받으면 앞의 주소를 덮어써 버립니다. 이전 일을 마칠 때까지 새 요청을 받지 않게 막는 안전장치입니다.
왜 if (AWVALID & AWREADY)가 아니라 if (AWVALID)인가요?AW_READY 상태에서는 AWREADY가 이미 1이니 뜻이 같습니다. 같은 블록에서 만든 AWREADY를 다시 읽으면 시뮬레이터가 "순환 조합회로" 경고를 내기 때문에 피했습니다.

③-2 AW 주소 저장: 악수하는 순간 받아 적기

악수가 끝나면 Master는 다음 클럭부터 주소를 더 이상 보장하지 않습니다. 그래서 악수하는 그 클럭에 AWADDR을 aw_addr_reg에 복사하고 aw_done을 켭니다.

사물함에 실제로 넣는 순간(reg_we)에 체크 표시를 지워 다음 쓰기를 받을 수 있게 합니다.

always_ff @(posedge ACLK) begin
    if (!ARESETn) begin
        aw_addr_reg <= 32'd0;
        aw_done     <= 1'b0;
    end else if (AWVALID & AWREADY) begin
        aw_addr_reg <= AWADDR;  // 받아 적기
        aw_done     <= 1'b1;    // 체크
    end else if (reg_we) begin
        aw_done     <= 1'b0;    // 체크 지우기
    end
end

④ W 채널: AW와 똑같은 틀

AW 코드에서 이름만 바꾼 것입니다. AW를 W로, AWADDR을 WDATA로, aw_addr_reg를 w_data_reg로 바꿔 읽으면 됩니다.

AW와 W는 서로 기다리지 않고 각자 따로 악수합니다. 어느 쪽이 먼저 끝나도 괜찮게 만든 이유가 다음 B 채널에 있습니다.

W_IDLE: begin
    if (WVALID & !w_done)
        w_state_next = W_READY;
end
W_READY: begin
    WREADY = 1'b1;
    if (WVALID)
        w_state_next = W_IDLE;
end
...
end else if (WVALID & WREADY) begin
    w_data_reg <= WDATA;   // 데이터 받아 적기
    w_done     <= 1'b1;
end

⑤ B 채널: 둘 다 받았으면 넣고, 영수증 주기

Slave 코드의 핵심입니다. B_IDLE 상태에서 aw_done & w_done, 즉 주소와 데이터를 모두 받았는지 확인합니다. 둘 다 받았으면 그 클럭에 reg_we를 1로 만들어 사물함에 넣으라고 신호하고, B_VALID로 넘어갑니다.

B_VALID에서는 BVALID=1, BRESP=2'b00(OKAY, 정상 처리)을 내보내고, Master의 BREADY가 오면 끝납니다.

always_comb begin
    BVALID = 1'b0;
    BRESP  = 2'b00;
    reg_we = 1'b0;
    b_state_next = b_state;
    case (b_state)
    B_IDLE: begin
        if (aw_done & w_done) begin  // 둘 다 받았나?
            reg_we = 1'b1;          // 사물함에 넣어라
            b_state_next = B_VALID;
        end
    end
    B_VALID: begin
        BVALID = 1'b1;              // 영수증
        BRESP  = 2'b00;             // OKAY
        if (BREADY)
            b_state_next = B_IDLE;
    end
    endcase
end

⑤-2 사물함에 넣기: 주소로 칸 고르기

reg_we가 1인 클럭에, 받아 둔 주소의 [3:2] 두 비트를 보고 네 칸 중 하나에 받아 둔 데이터를 넣습니다. 리셋하면 네 칸 모두 0으로 비웁니다.

이 블록의 case가 첫 시간에 배운 주소 디코더와 같은 역할을 합니다.

always_ff @(posedge ACLK) begin
    if (!ARESETn) begin
        slv_reg0 <= 0; slv_reg1 <= 0;
        slv_reg2 <= 0; slv_reg3 <= 0;
    end else if (reg_we) begin
        case (aw_addr_reg[3:2])
            2'd0: slv_reg0 <= w_data_reg; // 0x00
            2'd1: slv_reg1 <= w_data_reg; // 0x04
            2'd2: slv_reg2 <= w_data_reg; // 0x08
            2'd3: slv_reg3 <= w_data_reg; // 0x0C
        endcase
    end
end

⑥ AR 채널: AW와 같은 틀, 읽기용

AW와 구조가 같습니다. ARVALID가 오면 ARREADY로 악수하고, 악수 순간 ARADDR을 ar_addr_reg에 적고 ar_done을 켭니다.

다른 점은 체크를 지우는 때입니다. 읽기는 데이터 단계가 따로 없어서, R 채널이 꺼내 주기를 시작하는 순간(r_start)에 지웁니다.

end else if (ARVALID & ARREADY) begin
    ar_addr_reg <= ARADDR;  // 읽을 주소 적기
    ar_done     <= 1'b1;
end else if (r_start) begin
    ar_done     <= 1'b0;    // 꺼내 주기 시작
end

⑦ R 채널: 꺼낸 값 돌려주기

R_IDLE에서 ar_done이 켜졌는지 봅니다. 읽기 주소를 받은 뒤에만 응답해야 한다는 규칙(Read dependency)을 지키는 부분입니다. 켜져 있으면 r_start를 1로 만들고 R_VALID로 갑니다.

R_VALID에서 RVALID=1, RRESP=0(OKAY)을 내고 Master의 RREADY를 기다립니다.

실제 값 RDATA는 맨 아래 별도 블록이 정합니다. 받아 둔 읽기 주소의 [3:2]로 네 칸 중 하나를 골라 항상 연결해 둡니다. Master는 RVALID가 1인 순간의 값만 가져가므로, 평소에 다른 값이 보여도 문제없습니다.

R_IDLE: begin
    if (ar_done) begin       // 읽기 주소 받았나?
        r_start = 1'b1;
        r_state_next = R_VALID;
    end
end
R_VALID: begin
    RVALID = 1'b1;           // "여기 있어요"
    RRESP  = 1'b0;           // OKAY
    if (RREADY)
        r_state_next = R_IDLE;
end

// 사물함에서 꺼내기 (칸 고르기)
always_comb begin
    case (ar_addr_reg[3:2])
        2'd0: RDATA = slv_reg0;
        2'd1: RDATA = slv_reg1;
        2'd2: RDATA = slv_reg2;
        2'd3: RDATA = slv_reg3;
    endcase
end

권장

RRESP가 지금 1비트입니다. AXI 규격은 BRESP처럼 2비트 [1:0]이므로 Master와 Slave 양쪽을 같이 바꾸는 게 좋습니다.

권장

Master의 B·R 채널에 있는 if(BVALID & BREADY)는 같은 블록이 만든 BREADY를 다시 읽어서 시뮬레이터가 "순환 조합회로" 경고를 냅니다. 그 상태에서는 READY가 이미 1이므로 if(BVALID), if(RVALID)로 써도 뜻이 같습니다.
